# Лабораторная работа №4. Алгоритмы

В работе реализованы два способа подсчёта подъёмов по лестнице, пузырьковая сортировка, сортировка слиянием и стек.

## Установка и запуск

Команды выполняются из папки проекта. Нужен Python 3.10 или новее.

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install '.[dev]'
python -m pytest -v
python -m ruff check src tests
```

Код находится в `src/algorithmic_package`, тесты — в `tests`.

## Что реализовано

- **Лестница.** За шаг можно пройти одну или две ступени. Для нуля ступеней есть один способ — остаться на месте. Отрицательное число вызывает `NegativeNumberError`, неверный тип — `NotAnInteger`.
- **Сортировки.** Обе принимают список целых чисел и возвращают новый список по возрастанию. Для аргумента другого типа есть `InvalidDataTypeError`, для нецелого элемента списка — `NotAnInteger`.
- **Стек.** `push` добавляет элемент, `pop` снимает его, `peek` показывает вершину, `dup` дублирует вершину, `swap` меняет два верхних элемента местами. Работают `len` и `bool`. На пустом стеке `pop`, `peek` и `dup` вызывают `UndersizeError`. У `swap` та же ошибка, если элементов меньше двух.
- **Генераторы.** Есть случайный, отсортированный, обратный, почти отсортированный списки и список с большим количеством повторов. Для генераторов со случайностью одинаковый `seed` даёт одинаковый результат.

У Python есть предел глубины рекурсии. Текущее значение можно узнать через `sys.getrecursionlimit()`, а при превышении возникает `RecursionError`. В этой работе для рекурсивной версии отдельно стоит предел в 30 ступеней из-за большого числа повторных вычислений. При большем значении она вызывает `DeepRecursionError`. Для больших значений есть итеративный вариант.

## Сложность

Для лестницы `n` — число ступеней, для сортировок — длина списка.

| Алгоритм | Время | Дополнительная память |
|---|---|---|
| Лестница, рекурсия | O(2ⁿ) | O(n) на стек вызовов |
| Лестница, цикл | O(n) сложений | O(1) числовых переменных |
| Bubble Sort | O(n²) в худшем случае, O(n) на отсортированном списке | O(n) на копию |
| Merge Sort | O(n log n) | O(n) на временные списки |

У Merge Sort список делится пополам, поэтому уровней около log₂ n. На каждом уровне при слиянии обрабатывается суммарно n элементов.

Стек хранит n элементов и занимает O(n) памяти. Просмотр вершины, обмен, `len` и `bool` работают за O(1). Добавление, извлечение и дублирование занимают O(1) амортизированно.

## Бенчмарк

```bash
python -m algorithmic_package.benchmark
```

В таблице медиана пяти запусков в секундах. Перед каждым запуском делается новая копия исходного списка. Генерация и подготовка копии происходят до замера.

Замеры сделаны на macOS (arm64) с Python 3.14.2. Для почти отсортированного списка использовался `seed=52`.

| Тип входа | Размер | Bubble Sort, с | Merge Sort, с |
|---|---:|---:|---:|
| Отсортированный | 100 000 | 0.008797 | 0.311945 |
| Отсортированный | 1 000 000 | 0.087569 | 3.500694 |
| Отсортированный | 10 000 000 | 0.883774 | 38.709331 |
| Почти отсортированный | 100 000 | 0.014184 | 0.310490 |
| Почти отсортированный | 1 000 000 | 0.146371 | 3.492708 |
| Почти отсортированный | 10 000 000 | 1.397280 | 38.401377 |

Когда размер вырос со 100 000 до 1 000 000, на отсортированном списке время Bubble Sort выросло примерно в 10 раз, а Merge Sort — в 11 раз. Bubble быстро заканчивает работу, когда за проход нет обменов. В почти отсортированном списке генератор меняет местами только соседей в непересекающихся парах, поэтому Bubble тоже хватает двух проходов. Merge Sort продолжает делить и сливать списки на обоих входах, и время растёт примерно как n log n.
